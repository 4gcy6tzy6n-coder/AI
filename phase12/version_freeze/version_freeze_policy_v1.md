# Version Freeze Policy v1 - 版本冻结策略 v1

**版本**: v1.0  
**日期**: 2026-04-18  
**阶段**: Phase 12 - WP4: 全面上线前收口与版本冻结

---

## 1. 概述

本文档定义 Phase 12 版本冻结策略，确保 v1.2 版本作为正式上线候选版本的稳定性。

### 1.1 目标

- 建立版本冻结规则
- 规范变更流程
- 确保版本质量

---

## 2. 版本定义

### 2.1 版本号规则

```
v{主版本}.{次版本}-{标签}

示例:
- v1.2-rc1    # 候选版本 1
- v1.2-rc2    # 候选版本 2
- v1.2-launch # 上线版本
- v1.2.1      # 热修复版本
```

### 2.2 版本阶段

| 阶段 | 标签 | 说明 | 变更规则 |
|------|------|------|----------|
| 候选 | -rc{N} | 预发布候选 | 仅修复阻塞问题 |
| 上线 | -launch | 正式上线 | 禁止变更 |
| 热修复 | .{N} | 紧急修复 | 仅安全/关键修复 |

---

## 3. 冻结规则

### 3.1 冻结范围

| 类型 | 冻结内容 | 例外 |
|------|----------|------|
| 代码 | 功能代码 | 阻塞 bug 修复 |
| 配置 | 环境配置 | 紧急参数调整 |
| 文档 | 用户文档 | 错误修正 |
| 依赖 | 第三方库 | 安全更新 |

### 3.2 冻结时间线

```
功能冻结 ──▶ 代码冻结 ──▶ 候选版本 ──▶ 上线版本 ──▶ 热修复窗口
   │            │            │            │            │
  Week 6      Week 7       Week 8       Week 9       Ongoing
```

### 3.3 变更规则

| 阶段 | 允许变更 | 审批 | 测试 |
|------|----------|------|------|
| 功能冻结 | 阻塞 bug 修复 | 技术负责人 | 完整回归 |
| 代码冻结 | 仅阻塞 bug | 项目负责人 | 完整回归 |
| 候选版本 | 仅阻塞 bug | 双负责人 | 针对性测试 |
| 上线版本 | 禁止 | - | - |
| 热修复窗口 | 安全/关键 | 紧急流程 | 最小验证 |

---

## 4. 变更流程

### 4.1 标准变更流程

```
1. 提交变更申请
   └── 说明变更原因、影响、风险
   
2. 变更评审
   └── 技术评审 + 风险评估
   
3. 审批决策
   └── 根据阶段和级别审批
   
4. 实施变更
   └── 开发 + 代码审查
   
5. 测试验证
   └── 单元测试 + 集成测试 + 回归测试
   
6. 合并发布
   └── 合并到冻结分支
```

### 4.2 紧急变更流程

```
1. 紧急申请
   └── 说明紧急程度和影响
   
2. 快速评审
   └── 简化评审，快速决策
   
3. 即时审批
   └── 项目负责人 + 技术负责人
   
4. 快速实施
   └── 专注修复，最小改动
   
5. 验证发布
   └── 针对性测试，快速发布
```

### 4.3 变更申请表

```markdown
## 变更申请

### 基本信息
- **申请日期**: 
- **申请人**: 
- **变更类型**: 功能 / Bug 修复 / 配置 / 文档
- **紧急程度**: 标准 / 紧急 / 阻塞

### 变更描述
描述变更内容和原因

### 影响范围
- 代码影响: 
- 配置影响: 
- 文档影响: 
- 测试影响: 

### 风险评估
- 风险等级: 低 / 中 / 高
- 回滚方案: 
- 验证计划: 

### 审批记录
- 技术负责人: 
- 项目负责人: 
```

## 5. 分支策略

### 5.1 分支定义

| 分支 | 用途 | 保护级别 |
|------|------|----------|
| main | 开发主干 | 标准保护 |
| release/v1.2 | 冻结版本 | 严格保护 |
| hotfix/v1.2 | 热修复 | 标准保护 |

### 5.2 分支流程

```
main ──▶ release/v1.2 ──▶ tag: v1.2-rc1 ──▶ tag: v1.2-launch
              │
              └── hotfix/v1.2 ──▶ tag: v1.2.1
```

### 5.3 合并规则

| 方向 | 规则 | 审批 |
|------|------|------|
| feature → main | PR + Review | 团队 |
| main → release | 仅冻结期前 | 负责人 |
| hotfix → release | 紧急修复 | 双负责人 |
| release → main | 同步修复 | 自动 |

---

## 6. 热修复窗口

### 6.1 窗口定义

| 窗口 | 时间 | 用途 |
|------|------|------|
| 常规 | 每周二 10:00 | 计划内修复 |
| 紧急 | 随时 | 安全/关键修复 |

### 6.2 热修复标准

| 类型 | 定义 | 示例 |
|------|------|------|
| 安全修复 | 安全漏洞 | CVE 修复 |
| 关键修复 | 核心功能失效 | 服务崩溃 |
| 数据修复 | 数据损坏风险 | 数据丢失 |

### 6.3 热修复流程

```
1. 问题发现
   └── 监控告警或用户反馈
   
2. 影响评估
   └── 评估严重程度和影响范围
   
3. 紧急审批
   └── 项目负责人 + 技术负责人
   
4. 快速修复
   └── 专注修复，最小改动
   
5. 验证测试
   └── 针对性测试
   
6. 紧急发布
   └── 热修复窗口发布
   
7. 事后复盘
   └── 记录和总结
```
