## 1. 概述

本文档定义 Phase 12 Pilot 试运行的 Shadow 和 Canary 部署策略，确保系统安全、可控地接入真实流量。

### 1.1 目标

- 验证系统在真实流量下的表现
- 最小化对生产环境的影响
- 建立可观测、可回滚的试运行机制

### 1.2 策略对比

| 策略 | 流量比例 | 返回结果 | 风险等级 | 适用阶段 |
|------|----------|----------|----------|----------|
| Shadow | 100% | 否 | 极低 | 初期验证 |
| Canary | 5-50% | 是 | 低-中 | 逐步放量 |

## 2. Shadow 模式

### 2.1 架构设计

```
┌─────────────────────────────────────────────────────────────┐
│                         用户请求                             │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                      流量镜像器 (Mirror)                     │
│  ┌─────────────────┐    ┌─────────────────┐                │
│  │   生产系统      │◀───│    返回结果     │                │
│  │  (处理 & 响应)  │    │   (给用户)      │                │
│  └─────────────────┘    └─────────────────┘                │
│           │                                                │
│           │ 复制请求                                        │
│           ▼                                                │
│  ┌─────────────────┐    ┌─────────────────┐                │
│  │   Pilot 系统    │───▶│   记录日志      │                │
│  │  (仅处理)       │    │   (不返回)      │                │
│  └─────────────────┘    └─────────────────┘                │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 Shadow 配置

```yaml
# shadow-config.yaml
shadow_mode:
  enabled: true
  traffic_percentage: 100
  return_response: false
  
  request_mirroring:
    headers: true
    body: true
    timeout_ms: 5000
    
  response_handling:
    log_only: true
    compare_with_production: true
    
  safety_limits:
    max_concurrent_shadow: 100
    drop_on_timeout: true
    drop_on_error: true
```

### 2.3 Shadow 阶段目标

| 周次 | 目标 | 成功标准 |
|------|------|----------|
| Week 1 | 链路验证 | 无异常崩溃 |
| | 性能基线 | 延迟分布可接受 |
| | 日志完整 | 全链路可追溯 |

### 2.4 Shadow 监控指标

| 指标 | 阈值 | 告警 |
|------|------|------|
| Shadow 成功率 | > 95% | P1 |
| Shadow 延迟 P95 | < 2x 生产 | P2 |
| 资源使用 | < 80% | P2 |
| 错误率 | < 5% | P1 |

## 3. Canary 模式

### 3.1 架构设计

```
┌─────────────────────────────────────────────────────────────┐
│                         用户请求                             │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│                      流量分配器 (Router)                     │
│                                                             │
│     ┌─────────────────┐         ┌─────────────────┐        │
│ 95% │                 │         │                 │ 5%     │
│────▶│   生产系统      │         │   Pilot 系统    │◀───────│
│     │  (返回结果)     │         │  (返回结果)     │        │
│     └─────────────────┘         └─────────────────┘        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 灰度放量计划

| 阶段 | 流量比例 | 时长 | 用户范围 | 目标 |
|------|----------|------|----------|------|
| Canary 1 | 5% | 3 天 | L1 核心 | 初步验证 |
| Canary 2 | 10% | 3 天 | L1 + L2 | 扩大覆盖 |
| Canary 3 | 25% | 4 天 | L1 + L2 | 压力测试 |
| Canary 4 | 50% | 4 天 | 全部用户 | 接近生产 |

### 3.3 Canary 配置

```yaml
# canary-config.yaml
canary_mode:
  enabled: true
  
  rollout_steps:
    - name: "canary-5"
      weight: 5
      duration: 3d
      criteria:
        error_rate: "< 1%"
        latency_p95: "< 500ms"
      
    - name: "canary-10"
      weight: 10
      duration: 3d
      criteria:
        error_rate: "< 1%"
        latency_p95: "< 500ms"
        
    - name: "canary-25"
      weight: 25
      duration: 4d
      criteria:
        error_rate: "< 0.5%"
        latency_p95: "< 500ms"
        
    - name: "canary-50"
      weight: 50
      duration: 4d
      criteria:
        error_rate: "< 0.5%"
        latency_p95: "< 500ms"
        user_satisfaction: "> 4.0"
  
  routing:
    strategy: "header_based"  # header_based / random / user_hash
    header_name: "X-Pilot-User"
    
  rollback:
    auto_rollback: true
    triggers:
      - metric: "error_rate"
        threshold: "> 5%"
        duration: "5m"
      - metric: "latency_p95"
        threshold: "> 1000ms"
        duration: "5m"
```

### 3.4 路由策略

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| Header Based | 根据请求头路由 | 指定用户进入 Pilot |
| Random | 随机分配 | 均匀分布测试 |
| User Hash | 用户哈希 | 保证同一用户一致性 |

### 3.5 Canary 检查点

| 检查点 | 指标 | 阈值 | 动作 |
|--------|------|------|------|
| CP1 | 错误率 | < 1% | 继续放量 |
| CP2 | 延迟 P95 | < 500ms | 继续放量 |
| CP3 | 用户反馈 | > 3.5 | 继续放量 |
| CP4 | 资源使用 | < 70% | 继续放量 |

## 4. 降级与回滚

### 4.1 自动降级触发条件

| 条件 | 阈值 | 动作 | 恢复策略 |
|------|------|------|----------|
| 错误率飙升 | > 5% | 流量回切至 0% | 手动恢复 |
| 延迟飙升 | P95 > 1s | 限流 50% | 自动恢复 |
| 资源耗尽 | CPU > 90% | 拒绝新请求 | 扩容后恢复 |
| 依赖故障 | 检索服务 down | 关闭检索增强 | 依赖恢复后 |

### 4.2 回滚流程

```
1. 触发条件检测
   └── 自动或手动触发
   
2. 流量切换
   └── 100% 流量切回生产系统
   
3. 状态保存
   └── 保存 Pilot 系统状态
   
4. 问题诊断
   └── 分析日志和指标
   
5. 修复验证
   └── 修复后重新进入 Shadow
   
6. 恢复放量
   └── 从 Canary 5% 重新开始
```

### 4.3 回滚时间目标

| 场景 | RTO | 说明 |
|------|-----|------|
| 自动回滚 | < 1 分钟 | 触发条件后自动执行 |
| 手动回滚 | < 5 分钟 | 人工确认后执行 |
| 全量回滚 | < 10 分钟 | 包括数据回滚 |

| 指标 | 采集频率 | 告警阈值 |
|------|----------|----------|
| 流量比例 | 实时 | 偏离目标 |
| 错误率对比 | 5 分钟 | Pilot > 生产 2x |
| 延迟对比 | 5 分钟 | Pilot > 生产 1.5x |
| 用户反馈 | 实时 | 负面 > 20% |

### 5.3 对比分析

```python
# 生产 vs Pilot 对比
def compare_metrics(production, pilot):
    comparison = {
        "error_rate_diff": pilot.error_rate - production.error_rate,
        "latency_p95_diff": pilot.latency_p95 - production.latency_p95,
        "success_rate_diff": pilot.success_rate - production.success_rate
    }
    
    # 异常检测
    if comparison["error_rate_diff"] > 0.02:  # 2% 差异
        alert("Error rate degradation detected")
    
    if comparison["latency_p95_diff"] > 200:  # 200ms 差异
        alert("Latency degradation detected")
```

## 6. 人工复核

### 6.1 复核触发条件

| 条件 | 复核比例 | 说明 |
|------|----------|------|
| 英文任务 | 100% | 所有英文输出 |
| 置信度 < 0.7 | 100% | 低置信度结果 |
| 治理动作 = quarantine | 100% | 隔离对象 |
| 随机抽样 | 10% | 其他任务 |

### 6.2 复核流程

```
1. 任务标记为"待复核"
2. 分配给复核人员
3. 复核人员检查输出
4. 标记复核结果
   ├── 通过
   ├── 需改进
   └── 严重错误
5. 反馈至系统优化
```
