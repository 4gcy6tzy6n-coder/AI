# Stage 13 项目级原则与经验总结

## 项目级原则

### 核心原则：模型、数据、标签、评估四者必须一起治理

```
当单样本长期阻塞收口、且模型在其他同类样本上表现稳定时，
优先审查评估标签，再决定是否继续训练。
```

---

## 关键经验

### 1. 训练策略验证

| 版本 | 结果 | 关键教训 |
|------|------|----------|
| v2 | 陌生100%, 回归62.5% | 证明方向可学，但训练过偏 |
| v2.1 | 回归87.5%, 陌生55% | 平衡策略错误，数据构造有问题 |
| v3 | 回归87.5%, 正常100%, 陌生100% | 主线基本打通，仅1条标签问题 |
| v3-C | 全部100% | 修正错误标签后完全通过 |

### 2. 标签审查优先规则

**触发条件**（同时满足）：
- 单样本长期阻塞收口（其他指标已过线）
- 模型在该类样本上表现稳定（不是随机错误）
- 训练已达到合理轮次但无改善

**审查步骤**：
1. 确认模型预测与标签不一致
2. 从语义上分析该标签是否合理
3. 考虑该样本是否代表不同分布
4. 如确认标签错误，修正后重新评估

### 3. 数据构造规范

**v3推荐配比**：
- 回归保护集：40%
- 正常查询保护集：20%
- H2主攻失败集：25%
- 混合/边界样本：15%

**最低要求**：
- 回归保护集 ≥ 20条
- 正常查询必须单独保护
- 不能只有3-5条的"演示级"数据

### 4. 检查点选择策略

**硬门槛**：
- 回归 ≥ 95%
- 正常查询 ≥ 90%
- 陌生分布 ≥ 85%

**综合分**：
```
综合分 = 0.4×回归 + 0.35×陌生分布 + 0.25×正常查询
```

**选择规则**：
- 只有全部过硬的checkpoint才参与比较
- 否则即使陌生分布100%也不能算候选
