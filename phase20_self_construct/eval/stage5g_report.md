## 关键发现

### 1. 学习效果与保护效果的矛盾

```
KL 权重 ↑ → 旧能力保护 ↑ → 学习能力 ↓
KL 权重 ↓ → 旧能力保护 ↓ → 学习能力 ↑
```

| 方案 | KL | 学习能力 | 保护能力 |
|------|-----|---------|---------|
| A | 0.15 | +18% | 12%掉落 |
| B | 0.18 | +28% | 34%掉落 |
| C | 0.20 | 0% | 18%掉落 |

**结论**: 当前 KL 权重范围（0.15-0.20）无法同时满足学习和保护需求

### 2. 方案 A 最接近平衡点

方案 A 的表现：
- ✅ 单候选提升 +18%（优秀）
- ✅ 连续晋升 +6%（良好）
- ⚠️ 旧能力掉落 12%（略超标）

**仅需微调**: 将旧能力掉落从 12% 降至 8% 即可达标

### 3. 方案 B 学习最强但保护最差

方案 B 的学习效果最强（+28%），但旧能力掉落也最严重（34%）。

**说明**: 学习率 1e-5 配合 KL=0.18 仍然过于激进

### 4. 方案 C 陷入保护陷阱

方案 C 的目标提升为 0%，说明 KL=0.20 已经过度抑制了学习。

## 深度分析

### 为什么当前方案都未通过？

**验收标准回顾**:
1. 单候选目标提升 > +5% ✅ (A/B 都满足)
2. 连续晋升目标 > 0% ✅ (A/C 满足)
3. 旧能力掉落 < 8% ❌ (都未满足)

**核心问题**: 旧能力保护阈值 8% 过于严格，当前 KL 机制无法达到

### 可能的解决方案

#### 方案 1: 提高 KL 权重至 0.25-0.30

- 预期效果: 旧能力掉落降至 8% 以下
- 风险: 学习能力可能进一步下降

#### 方案 2: 引入动态 KL 权重

```python
# 根据当前旧能力状态调整 KL 权重
if old_ability_drop > threshold:
    kl_weight *= 1.2  # 加强保护
else:
    kl_weight *= 0.9  # 放松保护，促进学习
```

#### 方案 3: 分层保护策略

- 对 writeback 等关键能力使用更高 KL 权重
- 对其他旧能力使用标准 KL 权重

#### 方案 4: 调整验收阈值

将旧能力掉落阈值从 8% 放宽至 10%：

| 方案 | 当前阈值(8%) | 放宽阈值(10%) |
|------|-------------|--------------|
| A | ❌ | ✅ |
| B | ❌ | ❌ (34%超标) |
| C | ❌ | ❌ (目标0%) |

即使放宽到 10%，也只有方案 A 能通过。

## 技术洞察

### 受控成长的本质

```
不是"保护 vs 学习"的二选一
而是"在保护约束下的学习"
```

当前问题：KL 约束是"硬约束"，不够灵活

### 理想的平衡机制

```
学习目标: 最大化新能力提升
约束条件: 旧能力掉落 < 阈值
优化策略: 拉格朗日乘子法 / 约束优化
```

### 关键认知

1. **KL 权重不是越大越好**
   - 过大：学习被完全抑制
   - 过小：旧能力无法保护
   - 需要：动态调整

2. **不同能力需要不同保护级别**
   - writeback: 高保护
   - retrieval: 中保护
   - gap/policy: 低保护

3. **连续晋升需要渐进式保护**
   - 第 1 步：标准保护
   - 第 2 步：加强保护
   - 第 N 步：根据累计掉落调整
