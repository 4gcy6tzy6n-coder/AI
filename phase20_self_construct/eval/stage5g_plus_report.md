## 关键发现

### 1. writeback 专项保护非常有效 ✅

| 实验 | writeback 掉落 | 评价 |
|------|---------------|------|
| 实验 1 | 2% | ✅ 优秀 |
| 实验 2 | 2% | ✅ 优秀 |
| 实验 3 | 14% | ⚠️ 无专项保护时超标 |

**结论**: KL=0.30 对 writeback 的专项保护确实有效

### 2. 但其他旧能力仍在严重掉落 ❌

实验 2 中虽然 writeback 只掉 2%，但最大旧能力掉落达 24%，说明：
- **其他能力（retrieval_trigger、governance 等）受损严重**
- **需要扩展专项保护范围**

### 3. 学习能力与保护能力的矛盾依然存在

| 实验 | 目标提升 | 旧能力掉落 | 问题 |
|------|---------|-----------|------|
| 1 | +7% | 14% | 保护不足 |
| 2 | 0% | 24% | 学习被抑制 |
| 3 | +9% | 14% | 保护不足 |

**核心问题**: 固定 KL 权重无法同时满足学习和保护

## 深度分析

### 为什么分层保护还不够？

当前分层策略：
```python
kl_weights = {
    'gap': 0.18,
    'policy': 0.18,
    'governance': 0.20,
    'writeback': 0.30,
}
```

**问题诊断**:
1. **gap/policy 的 KL=0.18 仍然不够强**
   - 这些也是关键旧能力
   - 需要提高到 0.25-0.30

2. **所有旧能力都需要高保护**
   - 不只是 writeback
   - retrieval_trigger、governance、private_knowledge 都需要

3. **学习能力被过度抑制**
   - 当所有 KL 都提高时，学习率 8e-6 无法突破

### 根本解决方案

#### 方案 1: 全面提高 KL 权重 + 提高学习率

```python
kl_weights = {
    'gap': 0.25,
    'policy': 0.25,
    'governance': 0.25,
    'writeback': 0.30,
}
learning_rate = 1.2e-5  # 提高学习率补偿
```

#### 方案 2: 引入自适应 KL（轻量版）

```python
# 每 epoch 后调整
if old_ability_drop > 0.08:
    kl_weight *= 1.05
else:
    kl_weight *= 0.97
```

#### 方案 3: 分阶段保护策略

```python
# 第 1 步：标准保护
# 第 2 步：加强保护（累计掉落 >5% 时）
# 第 N 步：动态调整
```

## 技术洞察

### 受控成长的精确边界

通过 Stage 5E/5F/5G/5G+ 四阶段实验，我们已经精确测绘了平衡空间的边界：

```
Stage 5E: 学习 +28%, 保护 22% → 学习过强
Stage 5F: 学习 0%, 保护 4% → 保护过强
Stage 5G: 学习 +18%, 保护 12% → 接近平衡
Stage 5G+: 学习 +7%, 保护 14% → 需微调
```

**最优区间估计**:
- KL 权重: 0.22-0.28
- 学习率: 1e-5-1.2e-5
- 旧能力掉落: 8-10%

### 核心认知升级

1. **不是所有旧能力同等重要**
   - writeback: 必须 <5%
   - 其他: 可以 <10%

2. **分层保护是必要的**
   - 但当前分层粒度不够
   - 需要更细粒度的能力级保护

3. **固定参数难以达到精确平衡**
   - 可能需要自适应机制
   - 或更精细的手动调参
