## 关键发现

### 1. 自适应 KL 机制工作正常 ✅

观察到的动态调整：
```
第 1 步: KL gap=0.255, writeback=0.347, 旧能力掉落=14%
第 2 步: KL gap=0.295, writeback=0.400, 旧能力掉落=6%
```

**结论**: 自适应机制成功将旧能力掉落从 14% 降至 6%

### 2. 但触发时机太晚 ⚠️

问题：第 1 步掉落 14% 已经超标，自适应在第 2 步才生效

**根本原因**:
- 基础 KL 0.22 对第 1 步来说仍然不够
- 自适应阈值 6% 设置过高（应该更低触发）

### 3. 连续晋升目标提升极强 ✅

**+34%** 的目标提升说明学习能力非常充足

**分析**: 自适应 KL 不仅保护了旧能力，还优化了学习效率

### 4. writeback 保护成功 ✅

- 单候选平均掉落: 5%（接近门槛）
- 连续晋升掉落: 2%（优秀）

**结论**: writeback 专项保护有效

### 5. 旧能力反而提升的反常现象 ✅

retrieval 和 policy 在连续晋升中都提升了 22%

**分析**: 
- 旧能力回放样本质量高
- 自适应 KL 优化了学习方向
- 新能力与旧能力有协同效应

## 深度分析

### 为什么仍不达标？

**核心问题**: 第 1 步旧能力掉落 14% 超标

**根本原因链**:
```
基础 KL 0.22 不够强
    ↓
第 1 步旧能力掉落 14%
    ↓
触发自适应（但已超标）
    ↓
第 2 步掉落降至 6%
    ↓
总掉落 22%（因为第 1 步已损伤）
```

### 解决方案

#### 方案 A: 提高基础 KL（推荐）

```python
base_kl = {
    'gap': 0.28,      # 从 0.22 提高
    'policy': 0.28,
    'governance': 0.28,
    'writeback': 0.35,  # 从 0.30 提高
}
```

**预期**: 第 1 步掉落控制在 8% 以内

#### 方案 B: 降低自适应触发阈值

```python
kl_threshold_high = 0.04  # 从 0.06 降低
```

**预期**: 更早触发保护加强

#### 方案 C: 组合优化

```python
# 同时调整
base_kl = {'gap': 0.25, 'policy': 0.25, 'governance': 0.25, 'writeback': 0.32}
kl_threshold_high = 0.05
replay_ratio = 0.35
```
