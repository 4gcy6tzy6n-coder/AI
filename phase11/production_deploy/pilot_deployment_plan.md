**版本**: v1.0

**阶段**: Phase 11 - WP2: 生产部署基线建立

## 1. 概述

本文档定义 Phase 11 试运行（Pilot）部署计划，包括环境体系、部署方案、灰度策略和退出机制。

### 1.1 试运行目标

- 在受控环境下验证系统生产就绪性
- 收集真实场景下的性能和稳定性数据
- 验证监控、告警、回滚机制的有效性
- 为全面上线做准备

### 1.2 试运行范围

| 维度 | 范围 |
|------|------|
| 用户 | 内部测试用户 + 小范围邀请用户 |
| 流量 | 总流量的 5-10% |
| 功能 | 核心查询 + 治理链路 |
| 时间 | 2-4 周 |

## 2. 环境体系

### 2.1 环境矩阵

| 环境 | 用途 | 数据 | 访问控制 |
|------|------|------|----------|
| local | 本地开发 | 模拟数据 | 开发者 |
| dev | 开发集成 | 测试数据 | 开发团队 |

| pilot | 试运行 | 生产数据 | 受限用户 |

### 2.2 环境配置

```yaml
# pre-prod / pilot 环境配置
environment:
  name: pilot
  tier: production_candidate
  
  # 资源限制
  resources:
    cpu_limit: 4
    memory_limit: 8Gi
    storage_limit: 100Gi
  
  # 流量控制
  traffic:
    max_qps: 100
    max_concurrent: 50
    rate_limit_per_user: 10
  
  # 超时配置
  timeouts:
    retrieval_ms: 1000
    governance_ms: 2000
    memory_writeback_ms: 3000
    total_query_ms: 5000
  
  # 降级开关
  circuit_breakers:
    retrieval_timeout_enabled: true
    governance_fallback_enabled: true
    memory_async_writeback: true
```

## 4. 灰度发布策略

### 4.1 灰度阶段

| 阶段 | 流量比例 | 持续时间 | 检查点 |
|------|----------|----------|--------|
| 阶段 1 | 1% | 2 天 | 基础功能正常 |
| 阶段 2 | 5% | 3 天 | 性能达标 |
| 阶段 3 | 10% | 5 天 | 稳定性验证 |
| 阶段 4 | 25% | 7 天 | 全面验证 |
| 阶段 5 | 50% | 7 天 | 压力测试 |
| 阶段 6 | 100% | - | 全面上线 |

### 4.2 灰度规则

```python
# 灰度分流规则
def route_to_pilot(request) -> bool:
    """决定是否路由到 pilot 环境"""
    
    # 1. 白名单用户
    if request.user_id in PILOT_WHITELIST:
        return True
    
    # 2. 流量比例
    if random.random() < PILOT_TRAFFIC_PERCENTAGE:
        # 3. 一致性哈希，确保同一用户始终走同一路径
        user_hash = hash(request.user_id) % 100
        return user_hash < PILOT_TRAFFIC_PERCENTAGE * 100
    
    return False
```

### 4.3 灰度监控

| 指标 | 阈值 | 动作 |
|------|------|------|
| 错误率 | > 1% | 暂停灰度 |
| P95 延迟 | > 2x baseline | 暂停灰度 |
| 异常日志 | > 100/小时 | 告警 |
| 资源使用 | > 80% | 扩容 |

## 5. 回滚策略

### 5.1 自动回滚触发条件

| 条件 | 阈值 | 延迟 |
|------|------|------|
| 错误率飙升 | > 5% | 立即 |
| 服务不可用 | 健康检查失败 | 1 分钟 |
| 性能严重退化 | P95 > 5s | 5 分钟 |
| 数据异常 | 污染率 > 5% | 立即 |

### 5.2 回滚流程

```
1. 触发条件满足
   ↓
2. 自动告警通知
   ↓
3. 暂停流量接入
   ↓
4. 执行回滚命令
   ↓
5. 验证回滚成功
   ↓
6. 恢复流量接入
   ↓
7. 事后分析
```

### 5.3 回滚命令

```bash
# 一键回滚
./scripts/rollback.sh \
  --environment pilot \
  --version v1.0.0 \
  --reason "performance degradation"

# 验证回滚
./scripts/verify_rollback.sh --environment pilot
```

|----------|------|--------|----------|

### 6.2 恢复流程

```
1. 评估影响范围
   ↓
2. 选择恢复点
   ↓
3. 停止相关服务
   ↓
4. 执行数据恢复
   ↓
5. 验证数据完整性
   ↓
6. 重启服务
   ↓
7. 验证功能
```

### 6.3 灾难恢复

| 场景 | RTO | RPO | 恢复方式 |

| 数据损坏 | 1 小时 | 1 小时 | 备份恢复 |
| 全集群故障 | 4 小时 | 1 小时 | 异地恢复 |

## 7. 试运行退出条件

### 7.1 正常退出

| 条件 | 标准 |
|------|------|
| 运行时间 | > 2 周 |
| 成功率 | > 99.5% |
| 性能达标 | P95 < 2x baseline |
| 无 P0/P1 故障 | 连续 7 天 |
| 监控完备 | 所有指标可观测 |

### 7.2 异常退出

| 条件 | 动作 |
|------|------|
| P0 故障 | 立即回滚 |
| 连续 P1 故障 | 3 次后回滚 |
| 性能不达标 | 分析后决定 |
| 数据问题 | 立即回滚 |

### 7.3 退出流程

```
正常退出:
1. 提交试运行报告
2. 评审通过
3. 制定全面上线计划
4. 执行上线

异常退出:
1. 立即暂停流量
2. 执行回滚
3. 故障分析
4. 修复后重新 pilot
```
