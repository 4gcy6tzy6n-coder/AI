# ADR-0002: 记忆分层策略

## 状态
- 状态: 已接受
- 日期: 2026-04-17
- 作者: Post Transformer AI Team

## 背景

系统需要管理大量信息，从临时上下文到永久知识。我们需要一个分层策略来平衡访问速度、存储成本和数据持久性。

## 决策

我们决定采用 **四层记忆架构**:

1. **Transient (瞬态记忆)**: 秒级生命周期
2. **Long-term (长期记忆)**: 小时到天级生命周期
3. **Shallow Permanent (浅层永久记忆)**: 永久存储，压缩
4. **Deep Permanent (深层永久记忆)**: 永久存储，多重保护

## 分层详细设计

### Transient Layer
- **存储**: 内存
- **TTL**: 5 分钟
- **容量**: 1000 units
- **用途**: 当前会话上下文

### Long-term Layer
- **存储**: 内存 + 异步持久化
- **TTL**: 7 天
- **容量**: 10000 units
- **用途**: 会话历史，频繁访问数据

### Shallow Permanent Layer
- **存储**: SSD
- **TTL**: 永久
- **容量**: 500 GB
- **用途**: 验证后的知识

### Deep Permanent Layer
- **存储**: 分布式存储
- **TTL**: 永久
- **容量**: 无限制
- **用途**: 核心知识，审计日志

## 理由

### 为什么四层?

1. **访问局部性**: 80% 访问集中在 20% 数据
2. **成本效益**: 不同存储介质成本差异大
3. **可靠性**: 重要数据需要多重保护

### 数据流动策略

```
Transient → Long-term → Shallow → Deep
    ↑           ↑          ↑
  写入门    稳定性门   提升门
```

## 替代方案考虑

#### 替代方案 1: 单层内存
- **优点**: 简单
- **缺点**: 无法持久化，容量受限
- **结论**: 不适用

#### 替代方案 2: 双层 (缓存 + 存储)
- **优点**: 简单
- **缺点**: 无法满足不同持久性需求
- **结论**: 不够灵活

#### 替代方案 3: 五层或更多
- **优点**: 更精细
- **缺点**: 复杂度增加，收益递减
- **结论**: 过度设计

## 影响

### 正面影响
- 优化存储成本
- 提高访问效率
- 支持不同持久性需求

### 负面影响
- 增加系统复杂度
- 需要维护数据一致性
- 门控逻辑增加延迟

## 实施

### 配置示例
```yaml
memory_layers:
  transient:
    max_size: 1000
    ttl_seconds: 300
  long_term:
    max_size: 10000
    ttl_hours: 168
  shallow_permanent:
    storage: ssd
    compression: lz4
  deep_permanent:
    replication: 3
    backup: daily
```
