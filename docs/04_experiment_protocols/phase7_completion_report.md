## 4. 通用 Unit 抽象 v1

### 4.1 抽象成果

已定义四种通用 Unit 类型：

1. **Concept Unit** - 概念单元
   - 感知核心（语言相关）
   - 语义核心（跨语言通用）
   - 治理元数据

2. **Relation Unit** - 关系单元
   - 层级、因果、时序、空间、功能关系
   - 约束定义（domain、range、cardinality）

3. **Rule Unit** - 规则单元
   - 推理、转换、约束、偏好规则
   - 适用性定义

4. **Task Pattern Unit** - 任务模式单元
   - 分类、生成、推理、检索、验证任务
   - 执行流程定义

### 4.2 映射关系

| 中文原型 | 通用 Unit 类型 |
|----------|---------------|
| 汉字实体 | Concept Unit |
| 字音-字形映射 | Relation Unit |
| 字义演变规则 | Rule Unit |
| 构词模式 | Task Pattern Unit |
| 句法结构 | Relation Unit + Rule Unit |

### 4.3 适配层设计

- **中文适配层**: 笔画、部首、声调、字义演变等
- **英文适配层**: 词素、音节、重音、词义消歧等
- **通用治理机制**: 与语言无关的治理流程

## 6. 第七阶段回答的核心问题

### 问题 1: 相对于传统 Transformer 路线，系统赢在哪里？

**答案**:
1. **参数效率**: 利用率提升60%，更少的参数做更多的事
2. **可维护性**: 知识更新和错误修复效率提升数个数量级
3. **可扩展性**: 分层治理使系统更容易扩展
4. **透明度**: 知识存储和参数晋升可追溯

**代价**: 检索延迟增加4.9ms，架构复杂度提升

### 问题 2: 这套中文原型能不能提升为更一般的统一框架？

**答案**: 可以。

已通过通用 Unit 抽象 v1 证明：
1. 中文特有实现（字音、字形）可隔离在适配层
2. 核心治理机制（晋升、冲突检测、质量评估）是语言无关的
3. 四种 Unit 类型（Concept/Relation/Rule/Task Pattern）可覆盖多语言场景
