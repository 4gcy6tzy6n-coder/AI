### Phase 3: Prompt压缩优化 ⏳

**目标**: 减少Token数，降低生成负担

- [ ] 历史对话压缩
  - [ ] 只保留最近3-5轮（当前可能保留更多）
  - [ ] 长对话自动摘要
  - [ ] 去除无关上下文

- [ ] 检索结果精简
  - [ ] 限制检索结果数量（当前5条→3条）
  - [ ] 截断长内容（超过200字符截断）
  - [ ] 去除低相关性结果

- [ ] System Prompt优化
  - [ ] 精简指令描述
  - [ ] 去除冗余示例
  - [ ] 使用更短的变量名

**预期效果**:
- Prompt Token数减少 30-50%
- 总生成时间减少 20-30%

---

### Phase 4: 响应缓存策略 ⏳

**目标**: 缓存高频查询，避免重复生成

- [ ] 创建 `response_cache_v1.py`
  - [ ] 缓存键生成（查询+上下文哈希）
  - [ ] TTL机制（身份类缓存1小时，项目类缓存30分钟）
  - [ ] 缓存失效策略

- [ ] 可缓存查询类型
  | 类型 | 示例 | 缓存策略 |
  |------|------|----------|
  | 身份类 | "我叫什么名字？" | 缓存1小时 |
  | 项目状态 | "项目目标是什么？" | 缓存30分钟 |
  | 技术栈 | "技术栈是什么？" | 缓存1小时 |
  | 历史回顾 | "我们之前讨论过什么？" | 不缓存 |

**预期效果**:
- 高频查询TTFT < 100ms（命中缓存）
- 缓存命中率 20-30%

### Phase 5: 模型路由策略 ⏳

**目标**: 简单查询用更快模型

- [ ] 查询复杂度评估
  ```python
  def assess_complexity(query: str, context: Dict) -> Complexity:
      if is_greeting(query):  # "你好"
          return Complexity.LOW
      elif needs_retrieval(query):  # 需要检索
          return Complexity.HIGH
      elif is_factual(query):  # "Python是什么"
          return Complexity.MEDIUM
      else:
          return Complexity.HIGH
  ```

- [ ] 模型路由表
  | 复杂度 | 模型 | 预期延迟 |
  |--------|------|----------|
  | LOW | 轻量级模型/gpt-3.5-turbo | <500ms |
  | MEDIUM | 标准模型 | <2000ms |
  | HIGH | 主模型(deepseek-chat) | <4000ms |

**预期效果**:
- 简单问候TTFT < 500ms
- 整体平均延迟降低 20-30%

## TTFT 监控指标表

### 核心指标

| 指标 | 定义 | 当前值 | 目标值 | 监控方式 |
|------|------|--------|--------|----------|
| **TTFT** | Time To First Token<br>从用户输入到首Token | ~4700ms | <1000ms | 每个请求记录 |
| **TTF Ready** | Time To First Ready<br>从用户输入到可展示内容 | ~4700ms | <1200ms | 流式首块内容 |
| **Total Latency** | 总完成时间 | ~4735ms | <3000ms | 请求完成时记录 |
| **Streaming Latency** | 流式传输时间 | N/A | <2000ms | 首Token到最后Token |
