# Regression Gate Specification - 回归门禁规格

**版本**: v1.0  
**日期**: 2026-04-18  
**阶段**: Phase 10 - WP2: CI/CD 与持续回归体系

---

## 1. 概述

本文档定义 Phase 10 的回归门禁规格，确保每次代码变更都经过充分的自动化验证，防止质量回退。

---

## 2. 测试金字塔

### 2.1 测试分层

```
                    ┌─────────────┐
                    │   E2E Tests │  (5%)
                    │  端到端测试  │
                    └──────┬──────┘
                           │
              ┌────────────┴────────────┐
              │    Integration Tests    │  (15%)
              │       集成测试          │
              └────────────┬────────────┘
                           │
        ┌──────────────────┴──────────────────┐
        │          Service Contract Tests       │  (20%)
        │            服务契约测试               │
        └──────────────────┬──────────────────┘
                           │
     ┌─────────────────────┴─────────────────────┐
     │              Unit Tests                   │  (60%)
     │              单元测试                     │
     └───────────────────────────────────────────┘
```

### 2.2 各层测试定义

#### 单元测试 (Unit Tests)

| 属性 | 规格 |
|------|------|
| 覆盖率目标 | > 80% |
| 执行时间 | < 2 分钟 |
| 依赖 | 无外部依赖 |
| 并行度 | 可完全并行 |
| 失败策略 | 立即失败 |

**覆盖范围**:
- Core 模块 (gates, memory, tsla, unit)
- 工具函数
- 数据模型验证

#### 服务契约测试 (Service Contract Tests)

| 属性 | 规格 |
|------|------|
| 覆盖率目标 | 100% API |
| 执行时间 | < 5 分钟 |
| 依赖 | 服务模拟 |
| 失败策略 | 立即失败 |

**覆盖范围**:
- API 请求/响应格式
- 错误码验证
- 边界条件

#### 集成测试 (Integration Tests)

| 属性 | 规格 |
|------|------|
| 覆盖率目标 | 核心链路 |
| 执行时间 | < 10 分钟 |
| 依赖 | 真实服务 |
| 失败策略 | 立即失败 |

**覆盖范围**:
- 服务间调用
- 数据流验证
- 状态一致性

#### 端到端测试 (E2E Tests)

| 属性 | 规格 |
|------|------|
| 覆盖率目标 | 关键用户场景 |
| 执行时间 | < 20 分钟 |
| 依赖 | 完整系统 |
| 失败策略 | 立即失败 |

**覆盖范围**:
- 完整查询流程
- 治理流程
- 训练流程

## 5. CI 流程

### 5.1 提交级 CI (Commit-level)

**触发条件**: 每次代码提交

**执行时间**: < 5 分钟

**步骤**:
1. 代码风格检查 (30s)
2. 类型检查 (60s)
3. 单元测试 (120s)
4. 契约测试 (60s)

**失败策略**: 阻止提交

### 5.2 PR 级 CI (PR-level)

**触发条件**: PR 创建/更新

**执行时间**: < 15 分钟

**步骤**:
1. 提交级 CI 全部 (5min)
2. 集成测试 (10min)

**失败策略**: 阻止合并

### 5.3 合并级 CI (Merge-level)

**触发条件**: 代码合并到 main

**执行时间**: < 30 分钟

**步骤**:
1. PR 级 CI 全部 (15min)
2. 回归测试 (15min)

**失败策略**: 回滚合并

## 6. CD 流程

### 6.1 环境定义

| 环境 | 用途 | 部署方式 |
|------|------|----------|
| dev | 开发验证 | 自动部署 |
| staging | 集成验证 | 自动部署 |
| rc | 发布候选 | 手动触发 |
| prod | 生产环境 | 手动触发 |

### 6.2 部署流程

```
代码合并到 main
    │
    ▼
自动部署到 dev
    │
    ▼
运行冒烟测试
    │
    ├──(失败)──> 通知开发者
    │
    ▼(通过)
自动部署到 staging
    │
    ▼
运行完整回归
    │
    ├──(失败)──> 阻止进入 rc
    │
    ▼(通过)
等待手动触发
    │
    ▼
部署到 rc
    │
    ▼
运行验收测试
    │
    ├──(失败)──> 修复后重新触发
    │
    ▼(通过)
准备发布
```

### 6.3 回滚机制

| 场景 | 回滚时间 | 方式 |
|------|----------|------|
| dev 部署失败 | 自动 | 保持上一版本 |
| staging 回归失败 | 自动 | 阻止部署 |
| rc 验收失败 | 手动 | 重新部署上一 rc |
| prod 故障 | < 5 分钟 | 一键回滚 |

## 7. 夜间回归

### 7.1 执行计划

**频率**: 每日 02:00 UTC

**持续时间**: < 2 小时

**内容**:
1. 全量单元测试 (10min)
2. 全量集成测试 (30min)
3. 性能回归测试 (30min)
4. 双语回归测试 (20min)
5. 复杂知识回归 (20min)
6. Trace 异常扫描 (10min)

### 7.2 结果处理

| 结果 | 动作 |
|------|------|
| 全部通过 | 发送成功报告 |
| 部分失败 | 创建 Issue，通知负责人 |
| 严重失败 | 阻止次日发布，紧急通知 |
